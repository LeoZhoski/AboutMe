# AI 架构师笔记 (AI Architect Notes)

## 概述

这个文件夹包含 AI 生成代码的架构说明和修改指南，解决代码逻辑透明度问题。

当 AI 生成代码时，用户往往只能看到功能界面，但对背后的数据库设计、权限控制、核心业务逻辑等关键架构处于"黑箱"状态。当代码的逻辑无法通过视觉直接验证时，用户（尤其是低频编程者或产品经理）就失去了对系统的掌控感和信任感。

为了让0编程基础用户更好的理解整个项目的运行管线，请你在本文档库展示的代码片段中添加足够的注释，来实现自然语言级别的阅读效果。并在用户需要针对性的修改和升级功能时，能找到正确的参数和函数。

## 目标

- **理解架构**：清晰说明 AI 的设计思路和实现逻辑
- **掌握决策**：记录系统的关键技术决策和设计原因
- **指导修改**：提供具体的修改和扩展指导
- **避免风险**：预防技术债务和安全隐患
- **代码可读性**：**通过为代码片段提供自然语言级别的注释，确保非技术人员也能理解其核心功能和逻辑。**

## 使用指南

### AI 开发助手
每次生成或修改代码后，同步更新对应文档：
- 实现用户登录功能 → 更新 `authentication.md`
- 修改数据模型或字段 → 更新 `data-model.md`  
- 调整分类体系 → 更新 `domain-mapping-functions.md`
- 修改 API 接口 → 更新 `api-contracts.md`
- 更改状态管理 → 更新 `state-management.md`

**重要**：在更新前先检查是否已有相关文档，避免创建重复文档。

## 文档规范

### 内容要求
- **功能说明**：清晰描述功能作用和实现方式
- **设计原因**：解释技术选型和架构决策
- **修改指导**：提供具体的修改步骤和注意事项
- **风险提示**：标明潜在风险和限制条件
- **代码注释**：**为代码片段提供恰当的注释，让产品经理等非技术人员能够理解业务意图和关键逻辑。**

#### 代码注释原则

**核心原则**：解释"为什么"和"是什么"，而非"做什么"

1. **避免过度注释**：不要对显而易见的代码进行冗余解释
2. **专注业务意图**：重点解释业务目的、设计决策和关键逻辑
3. **分层次注释**：根据代码复杂度选择合适的注释详细程度

#### 注释详细程度指导

**需要详细注释**：
- 数据访问层、业务逻辑层等复杂组件
- 包含复杂业务规则和决策逻辑的代码
- 涉及性能优化策略的关键代码
- 数据流转复杂的处理逻辑

**可以简化注释**：
- 简单UI组件和工具函数
- 静态配置信息
- 字段含义明显的类型定义

**注释的核心价值**：
- 为产品经理提供业务上下文
- 为新开发者提供系统理解
- 为维护者提供设计决策背景
- 为调试者提供数据流转路径

#### 快速参考

**✅ 有价值注释**：
```typescript
// 防止投票数变为负数，确保数据一致性
const newVoteCount = voteType === 'up' ? currentVotes + 1 : Math.max(0, currentVotes - 1);
```

**❌ 冗余注释**：
```typescript
// 获取当前记录
const record = await this.getIntelligenceById(id);
```

**详细示例和模板**：参见 [annotation-examples.md](./annotation-examples.md)

### 🚫 文档重复性约束（重要）

为避免文档重复和维护困难，严格遵守以下约束：

1. **单一数据源原则**
   - 每个技术领域只维护一个权威文档
   - 避免在多个文档中描述同一功能的不同方面
   - 相关内容通过引用链接组织，而非重复描述

2. **文档职责边界**
   - `data-model.md`: 数据结构、字段定义、类型系统
   - `api-contracts.md`: API 接口、请求/响应格式
   - `state-management.md`: 状态管理策略、数据流
   - `domain-mapping-functions.md`: 业务逻辑函数、映射关系

3. **禁止创建重叠文档**
   - 不创建只描述某一方面细节的文档
   - 不为同一数据源创建多个定义文件
   - 不将配置信息分散在多个文档中
